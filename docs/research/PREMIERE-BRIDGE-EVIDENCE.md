# Premiere bridge research: actual projects, not just XMP packets

Research date: 2026-11-12. Proposal/evidence only. No application was launched, project/media modified, plugin installed, commit pushed or release published for this research.

## Conclusion

Use a small official UXP plugin inside Premiere as the deterministic native-project writer. Field Lab's local service should send typed, revisioned metadata/selection operations; the plugin resolves known clips, applies bounded transactions, reads results back and saves through Premiere. XMP is an interchange projection, not the authoring format for bins, sequences, proxy attachments or the complete project graph. The useful product is an editable source library: native transcript, metadata columns, range markers, searchable bins, carefully generated selects sequences and optional subclips.

The installed Mac has `/Applications/Adobe Premiere Pro 2025/Adobe Premiere Pro 2025.app` **25.6.6** (build 25.6.6.5) and `/Applications/Adobe Premiere Pro 2026/Adobe Premiere Pro 2026.app` **26.2.2** (build 26.2.2.3), observed read-only from application Info.plists. Neither is a live runtime capability test. Current docs describe APIs newer than these installs; a website method is not proof that this Mac supports it.

## Documented native API evidence

| Need | Official API evidence | Consequence |
|---|---|---|
| Create/open/save a real `.prproj` | [`Project`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/project): `createProject`, `open`, `importFiles`, `save`, `saveAs`, `executeTransaction`, `lockedAccess` since 25.6. | Premiere can own project creation and serialization. `saveAs` changes the active project and the existing Project object's identity/path; it is not an invisible detached snapshot export. |
| Bins and Search Bins | [`FolderItem`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/folderitem): `createBinAction`, `createSmartBinAction(name, searchQuery)`, move/rename actions since 25.6. | Search Bin creation is not absent from UXP. However query grammar/field matching are not specified by this class reference. |
| Project metadata and file-XMP view | [`Metadata`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/metadata): project/XMP getters; project setter with updated-field list; XMP setter; custom project schema and panel-column methods since 25.6. | Prefer project-specific metadata writes where originals must remain byte-identical. The XMP setter description alone does not establish whether media/sidecars are written. Test preferences and actual files. |
| Clip and sequence range markers | [`Markers`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/markers): `getMarkers` accepts either sequence or clip; add action takes name, type, start, duration, comments since 25.6. | Timed annotation/visual-note projections need not become thousands of duplicated source clips. |
| Native transcript import | [`Transcript`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/transcript): `importFromJSON`, `createImportTextSegmentsAction`, `exportToJSON` since 25.6. | Parakeet transcript can target Premiere's native transcript, not only caption tracks or marker text. `hasTranscript` is newer (26.3). |
| Native subclips/proxies | [`ClipProjectItem`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/clipprojectitem): proxy attachment/availability since 25.6; `createSubClipAction` since **26.3**. | Local 26.2.2 cannot be assumed to support UXP subclip creation. Proxies and subclips are different native structures, not XMP fields. |

Adobe's [official sample panel](https://github.com/AdobeDocs/uxp-premiere-pro-samples/tree/main/sample-panels/premiere-api) provides corresponding modules. Its [projectPanel.ts](https://github.com/AdobeDocs/uxp-premiere-pro-samples/blob/main/sample-panels/premiere-api/src/projectPanel.ts) demonstrates a smart-bin action with a simple literal search query, but does not establish rich boolean/custom-column query syntax. Its [metadata.ts](https://github.com/AdobeDocs/uxp-premiere-pro-samples/blob/main/sample-panels/premiere-api/src/metadata.ts) distinguishes a full XMP-packet setter from project metadata with `updatedFields`; copying an entire packet from another clip, as its demonstration does, is unsuitable for a merge-preserving production synchronizer.

Adobe's [UXP getting-started instructions](https://developer.adobe.com/premiere-pro/uxp/plugins/) require Premiere 25.6+ and show the plugin running inside the application. Research did not locate a documented standalone/headless `.prproj` authoring SDK. This is a bounded research finding, not a claim that no third party has ever reverse-engineered that file. Do not continuously rewrite a gzip/XML project file behind Premiere's in-memory model: use the host's save operation. A project can be current only as of the last successfully applied **and saved** revision; if Premiere is closed or disconnected, pending operations remain pending.

## Transcript import is unusually promising

Adobe publishes the [audio transcript JSON schema](https://github.com/AdobeDocs/uxp-premiere-pro-samples/blob/main/sample-panels/premiere-api/assets/transcript_format_spec.json) and an [import example](https://github.com/AdobeDocs/uxp-premiere-pro-samples/blob/main/sample-panels/premiere-api/src/transcript.ts). The schema has `language`, speech `segments` and `speakers`; segments reference speaker UUIDs, and words carry timed starts/durations and confidence. Extra arbitrary fields are forbidden. Use a persisted mapping from Field Lab person/voice identity to transcript speaker UUID, preserving names confirmed by the operator. Do not invent confidence values or word-level precision not produced by the transcription/alignment pipeline; define and validate an explicit unknown-confidence policy. Face-visible identity is not automatically the identity of a speaking voice.

The sample converts JSON using `Transcript.importFromJSON`, then commits `createImportTextSegmentsAction` inside a locked transaction. A spike must still verify imported text appears in Text-Based Editing, timing is correct, speaker names survive reopen, transcript export roundtrips, and a second import does not overwrite an editor's corrections. This is not the same route as importing an `.srt` subtitle file.

## Exact search results can become real timelines without masterclip In/Out edits

[`SequenceEditor.createInsertProjectItemAction`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/sequenceeditor) exists since 25.6 but takes timeline position/tracks, not explicit source range parameters. [`VideoClipTrackItem`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/videocliptrackitem) and [`AudioClipTrackItem`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/audiocliptrackitem) expose per-instance source In/Out and timeline Start/End actions since 25.6. Proposed older-host route: insert into a new plugin-owned sequence, trim the generated A/V track instances to the retrieved range and place successive results contiguously. This avoids changing the editor's masterclip In/Out, but linked audio/video behavior, frame/tick rounding, handles and overlap/ripple effects require a native test.

[`SourceMonitor`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/sourcemonitor) can open a project item on 25.6, but setting its position arrives in **26.3**. [`Sequence.setPlayerPosition`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/sequence) is 25.6. Therefore current-host fallback for a web result's precise timestamp is a generated sequence with a known range-to-timeline mapping; direct source-monitor timestamp jumps need a newer host or an explicitly validated compatibility route.

A native Search Bin remains a metadata query. Semantic/image retrieval stays in Field Lab; its saved result set can become a named, revisioned selects sequence or bin of subclips once supported. If results change after an editor starts cutting from a selection, publish a new revision rather than unexpectedly rearranging their timeline.

## Reuse choices

1. **Preferred deterministic core:** direct Adobe UXP + typed host declarations, official examples and built-in [`require('uxp').xmp`](https://developer.adobe.com/premiere-pro/uxp/uxp-api/reference-js/modules/uxp/xmp/getting-started/xmp). `XMPMeta` provides RDF/property operations and serialization, while `XMPFile` directly accesses files. Preserve unknown namespaces/properties and update only owned fields. A local authenticated queue transport is sufficient; it need not include an LLM.
2. **Optional agentic adapter to evaluate:** [`leancoderkavy/premiere-pro-mcp`](https://github.com/leancoderkavy/premiere-pro-mcp), currently documenting v1.30.0, MIT, a local authenticated UXP connector and separately scoped CEP compatibility. It is independent of Adobe and explicitly separates package/CI checks from live-host verification. Useful tool reuse, but its broad mutation/QE surface is larger than a metadata synchronizer needs. Pin and audit a narrow authority/capability profile; prove native readback. Do not silently fall back to a different mutation route after an uncertain failure.
3. **Avoid as a new foundation:** [`Pymiere`](https://github.com/qmasingarbe/pymiere) now explicitly says it is not maintained. Its Python-to-ExtendScript bridge remains a compatibility reference, not the preferred new background service.
4. **Interchange fallback:** OTIO/FCP XML for one-shot selects/rough-cut import, not synchronization of a complete project. [OTIO uses adapters](https://opentimelineio.readthedocs.io/en/latest/tutorials/adapters.html); conversion fidelity depends on the adapter and host. Premiere's [`ProjectConverter`](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/projectconverter) documents FCP XML/OTIO sequence **exports** since 26.2 and AAF since 26.3. Export support does not by itself prove complete project import/roundtrip. Adobe's [migration help](https://helpx.adobe.com/premiere/desktop/organize-media/import-files/migrate-from-final-cut-pro-x.html) is a migration route, not a live-project merge contract.

## Do not wait for Adobe's newly announced local MCP

Adobe's November 10 [Creative Cloud MAX release](https://news.adobe.com/news/downloads/pdfs/2026/11/creative-cloud-release-max-2026.pdf) previews third-party agents changing editable native local projects, but its availability section says **private beta in early 2027**. This does not provide a public installable Premiere MCP contract today, a supported headless writer or a promise of local Qwen compatibility. Track it as a future transport option. The public UXP plugin approach is actionable independently of that announcement.

## Offline runtime requirement

All ordinary synchronization must run **inside Field Lab's code plus its local Premiere plugin**, without Codex, a runtime agent, MCP client, cloud inference, API key or network service. An agent may help develop/install/debug the software when internet is available, but it is not part of the field pipeline. The optional third-party MCP research above is not a proposed runtime dependency.

Bundle the plugin code, schema validator, XMP manipulation code and any UI assets locally. Use an authenticated loopback connection restricted to `127.0.0.1`, or a local revisioned file journal in an operator-approved directory. Model output becomes typed metadata/selection data, never arbitrary UXP code. The plugin's static manifest must declare only the required local filesystem/network permissions; approve and persist its local-folder access through supported UXP mechanisms during setup. No CDN scripts, remote schema fetches, telemetry requirement or fallback to an online agent.

Offline readiness must report the host build, actual method availability, loaded plugin, approved project folder, reachable local service, current project/writable state, last applied revision and last **saved** revision. If the plugin/host is closed or unavailable, Field Lab retains pending revisions and the existing saved project remains usable; it must not claim that an unsaved update reached disk. First-time Adobe licensing/plugin distribution and the user's existing offline licensing eligibility are separate prerequisites, not evidence of a cloud dependency in our sync design.

## Field Lab API and plugin transport (design inference)

Adobe explicitly documents [WebSocket clients only](https://developer.adobe.com/premiere-pro/uxp/resources/recipes/network/): a UXP plugin cannot host a WebSocket listener or accept incoming connections. Its network recipe also warns that macOS restricts insecure HTTP. Do not assume Node's `http.createServer` or a raw TCP listener is available inside UXP, and do not promise an untested `fetch(http://127.0.0.1)` route on this Mac.

Expose the Field Lab-specific API from the **existing local Python service**. The Premiere plugin initiates a persistent, authenticated outbound connection to that service (prefer a host-validated local WebSocket transport; approved local file journal is a fallback). The web UI sends its requests to the same Field Lab service; requests then travel over the already-connected plugin session. From the filmmaker's perspective this is one local Premiere API, even though its listening socket lives outside Premiere.

Use an operator-paired local token scoped to the project and session, a plugin-generated session nonce, a protocol version and capabilities handshake, project GUID/path validation, operation IDs and explicit saved-revision acknowledgments. Bind only loopback, reject remote URLs/origins, and reconnect with a bounded backoff. Host permissions/TLS/localhost behavior must pass the first native spike; do not disable certificate validation or silently expand to arbitrary network access to make it work. If a host demands broader manifest declarations, report that explicit constraint and retain a runtime loopback allowlist rather than pretending permissions are narrow.

The API should have only bounded typed operations such as `health`, `projectInfo`, `syncBatch`, `revealAsset`, `createSelects`, `readEdits` and `save`. `syncBatch` accepts known asset IDs, revisions and permitted field/marker/transcript changes—not arbitrary JavaScript. `createSelects` accepts validated source ranges and a plugin-owned output target—not arbitrary timeline editing instructions. Reject an unexpected project or editor-owned sequence. No eval endpoint, shell commands, generic "execute code" tool or wide MCP mutation catalog is needed. The local Qwen/search engine can choose requested content through existing retrieval, but deterministic code validates and performs every native operation.

## Proposed continuous-project contract (design inference)

- Keep SQLite as the transactional identity/provenance/edit-history store; create standard XMP projections for interoperable metadata. Never store face/voice vectors or the entire graph as opaque XMP required to use the edit.
- Assign stable source asset IDs plus native project GUID/item identity mappings. File paths are locators; distinguish multiple project items/subclips referencing the same media.
- Deliver an idempotent outbox operation with object ID, changed fields, base revision, ownership and desired hash. Do not execute instructions found in transcripts or arbitrary project metadata.
- The plugin is the single writer for its native project operations. Build actions under `lockedAccess`, use a named undoable transaction, read back affected objects, save with `Project.save`, then acknowledge the saved revision. Do not call `saveAs` as a background snapshot without accounting for its active-project switch.
- Preserve editor-owned bins, sequences, markers, transcript corrections, label choices and metadata. Generated objects get ownership IDs; a user-modified generated sequence is frozen/forked rather than overwritten. Shared human fields use three-way merge/conflict review, not last-writer-wins.
- XMP, SQLite and `.prproj` are not one atomic filesystem transaction. Keep separate per-target applied/saved revisions, retry after interruption, and reconcile readback before replay. A crash after a native commit but before acknowledgment must not duplicate clips/markers.
- Default to a managed source-library project or clearly bounded managed bin. If using Productions, respect the actual writable project/lock context. An editor can own separate assembly projects; cross-project masterclip/metadata propagation needs its own test rather than an assumption.

## Highest-value spike tests

1. Capability report on installed 26.2.2 and a reviewed 26.3+ disposable host; exact API calls/version inventory, no automatic app upgrade.
2. Own short MP4/MOV/WAV copies: update project metadata versus XMP getter/setter/sidecar through supported routes; hash originals before/after, save/reopen, test unrelated namespace preservation and externally changed sidecar visibility.
3. Create one custom field and one Search Bin; determine actual query syntax/field matching (including custom fields, markers and native transcript text) through visible results, not method names.
4. Import native transcript JSON with genuine word times/two known speaker names; verify Text-Based Editing, corrections and export/reopen fidelity.
5. Add one ranged clip marker and generated selects sequence with two exact ranges and linked audio. Verify frame/timecode, source-monitor/version behavior, soft subclip handles if 26.3+, and no masterclip trim changes.
6. Interrupt at native transaction/readback/save/ack boundaries. Relaunch/reconcile without duplicate objects or lost human edits; preserve an unrelated edited sequence byte/semantic behavior.
7. Reconnect and resume from a closed project; show the last saved revision versus current Field Lab revision honestly. No claim of continuous `.prproj` updates while the required host bridge is unavailable.
