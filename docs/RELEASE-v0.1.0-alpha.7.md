# Unreleased draft — smaller-drive backup rotation

Work in progress. No release or tag is published for this change. Publication requires an explicit request from the maintainer.

Opt-in backup rotation adds a local **Back up pending footage** interface and managed CLI. It discovers accepted verified OffShoot queue entries, allocates whole cards across registered backup drives with a 10% reserve, and preserves the current date/card ingest hierarchy through fixed APFS copy-on-write source projections. CCC starts only explicitly registered dedicated tasks; independent SHA-256 destination verification gates completion.

A checksummed atomic ledger, cross-process locking, durable staging and copy-attempt commits support restart/reconciliation. A surviving CCC task is never stopped or blindly relaunched. Unknown attempts are verified after CCC becomes idle; incomplete work remains assigned for retry. Each connected drive receives a recovery ledger outside CCC's destination subtree. Capacity/UUID/physical backing are checked before copying and destination identity is checked again before success.

Project sidecars use immutable metadata generations: SQLite's backup API includes committed WAL edits; regular files use APFS clones. Identical generations are reused. Later operator notes/names/chat can be backed up without another media analysis. Offline drives retain older revisions until reconnected. Search projections may lag the transactionally consistent metadata database and should be reconciled on restore.

The optional setup creates empty managed source folders, but never creates/edits/disables/deletes CCC tasks or changes OffShoot destinations. New dedicated CCC tasks and secured standalone preflight guards require recipient-machine UI/admin setup and explicit acceptance. Existing tasks were not changed or started during development. Ordinary installation/update does not enable this feature.

Compatibility: new separate JSON rotation schema 1; no project SQLite schema migration, model change, analysis profile change or AI reindex. Preserve the primary state and spool across upgrades; older releases do not operate rotation. This is a partitioned archive, not an automatic mirror of arbitrary later Finder reorganizations. Retained metadata generations/clones consume space and are never silently pruned.

Validation: 348 local tests passed on the pinned Python 3.12.16 runtime, including 80 backup tests. Independent buddies reviewed the architecture, physical-volume resolver, privileged-script boundary and recovery behavior. Tests exercise real manager SIGKILL before launch, after simulated copy and after hash checks; ongoing CCC status, whole-card rotation across different capacities, closed older drive offline, changed UUIDs/bytes, malformed state, traversal/symlinks, low space after allocation, concurrent initialization/workers, durable ledger recovery and live SQLite WAL restoration. Native macOS tests exercise actual APFS clone independence and generated guard execution with a fixture diskutil transport. Browser testing exercised the run button and visible completion with disposable simulated copies. GitHub CI runs the backup tests on Linux and macOS in addition to the existing release checks.

These are fake-CCC/process-interruption tests, not real CCC transfers, hardware power-pull testing or completed field acceptance. Read-only inspection confirmed the attached ThunderBlade SoftRAID driver's eight physical member mapping. Its APFS volume was unavailable during validation; no repair/mount/format action was attempted. Full mounted primary/backup identity, new CCC task/guard, copy, verification, media and metadata restore acceptance remains required on actual drives. AI/model/UI runtime behavior outside the optional backup interface is unchanged; no full fresh model installation or reindex was performed for this feature.

See [setup, recovery and physical acceptance](BACKUP-ROTATION.md). The deployment skill and install/update prompts link the same procedure and preserve existing task configurations.
