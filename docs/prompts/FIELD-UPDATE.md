# Field update: paste into Codex when internet is available

This is the software deployment subprocedure. The default repository-URL update starts at [docs/UPDATE.md](../UPDATE.md), which resolves a release and follows only its manifest-required migrations. Alpha.11 adoption preserves the existing ingest destination, CCC tasks and Backup binding; older configuration migrations are not replayed. The user never needs to paste this expanded prompt. Only an explicitly software-only request stops after this subprocedure.

Replace `RELEASE` with the maintainer's release/tag or full commit. Keep the previous release until the new one is checked.

```text
Update my installed Field Lab workflow from https://github.com/mattb/field-lab-deployed to RELEASE. Read the checkout's AGENTS.md, docs/UPDATE.md, docs/MULTI-PRIMARY-ADOPTION.md, docs/OPERATIONS.md, docs/UPGRADES.md and this release's compatibility/validation notes. Inspect the actual installed release, configured drive UUID, service status, queue, free storage and source checkout before changing anything.

Preserve the checkout's local changes. Fetch the exact requested ref and prepare a separate candidate using the repository's deployment scripts while the current version remains installed. Do not pull into the active release. Reuse verified local downloads; if internet fails, leave the current release active and report the incomplete preparation. A code/model dependency change must pass its local readiness checks, not just exist on disk.

Keep all media, _DIT_NOTES databases, operator names/notes/links, transfer receipts, durable queue and machine settings. Do not copy sample databases, reset identities, clear indexes, change the configured drive or rewrite OffShoot/CCC preferences. Stop before a schema-incompatible update unless the documented backup/compatibility plan protects subsequent operator edits. Use SQLite's backup API if a metadata backup is required; do not copy a live database without its WAL.

If a MacDroid/MTP camera source is in use, read docs/MACDROID-INGEST.md and preserve its current configuration. This documentation update does not authorize installing an adapter or changing camera settings. A source-adapter change needs the documented camera-specific transfer/interruption checks; cached source verification is not proof of independent device rereading.

Before activation, follow docs/MULTI-PRIMARY-ADOPTION.md to capture exact current ingest config, Backup binding, registry if present and read-only CCC task inventory. Keep the printed receipt ID for the after-update check. This update does not configure a destination, initialize a shoot registry, change CCC tasks/filters/endpoints/schedules, bind Backup or perform a cutover. A missing old CCC migration receipt is not permission to set it up. Existing single-primary installations stay single-primary until a separately requested cutover. Before activation, establish a quiet moment with no OffShoot copy and no AI or chat work in progress. If work is active, finish preparing but defer activation. Stop the existing service cleanly, activate atomically through the provided manager, and check readiness. Before restarting, use the read-only reindex plan for each relevant existing media project to distinguish a new analysis profile from a UI/search-only upgrade. Show analyze/reuse counts. If this update request or the release instructions expressly request reanalysis of those registered scopes, run the managed resumable reindex process during the quiet period. Otherwise do not start a new analysis backlog without explaining it to the operator; service startup also reconciles against the new profile. A React-only update should reuse complete analysis and does not need ASR/VLM work. Refresh Desktop apps and run the preservation check before ordinary restart. Restart only after preservation passes and the chosen scope/backlog is understood, then inspect status/reconciliation. A pending cutover blocks ordinary restart and remains an explicit recovery task. If health checks fail, use the documented code rollback; never overwrite newer operator data with an older backup automatically.

Run the supplied deployment tests and local offline readiness check. Reopen the existing library and verify an existing name/note, then use a disposable small clip for any new processing behavior. Read docs/UPGRADES.md. If I request reanalysis after a prompt/model change, plan the registered project scopes with reindex, report the work, then run it while the service is stopped using --run --offshoot-idle. This request authorizes that reanalysis. If I have not requested it, do not reanalyze all footage merely as an update smoke test. A React-only update should reuse analysis; reload the browser after restarting the server. Explain any deferred mounted-drive/physical-transfer tests. Preserve CCC configuration and the previous release. Alpha.11 follows preservation-only adoption after activation; never execute old manifest migrations cumulatively from changelog history. Refresh the recipient Desktop apps with bash deploy/bootstrap.sh desktop using the same --home. This includes Backup; preserve its shared current-task binding and do not start it as an update test. If unbound, retain that state and report it; do not configure or bind a task during this update. Run the preservation check after activation/Desktop refresh and before ordinary restart. A pending cutover remains pending and blocks normal startup; preserve its journal rather than finishing or clearing it.

Report old/new commit, checks run with results, remaining backlog, any needed operator action, and the rollback command. Do not format cards, delete old releases automatically or describe unrun checks as passed.

If date-filter backup rotation was explicitly configured, read docs/BACKUP-ROTATION.md and preserve its private assignments, verification records and CCC task exports. Do not stop an active CCC task or reset a ledger. Leave filters/endpoints unchanged during software activation; afterward perform only the selected manifest’s preservation checks. Do not configure CCC as an alpha.11 update step. The earlier rotation implementation is withdrawn; do not invoke its former commands or remove existing backup data. The supported plan uses CCC UI-managed Include filters for previous sets and an Exclude filter for the current set. No AI reindex is needed for documentation or planning changes.
If this deployment includes the Premiere bridge, follow docs/PREMIERE-INSTALL.md. Use only a CCX produced by the checked-in pinned Adobe SDK packager or Adobe UDT whose runtime payload and module hashes match the sealed candidate. Do not fabricate an installer ZIP, change Adobe registries, or enable developer mode as the production installation path. Save and quit Premiere before the UPIA install/update; reopen and verify a fresh saved operation with the actual project bridge receipt/database before reporting the plugin ready. Preserve pairing, journals and every project annotation. An interrupted install needs premiere reconcile, not clearing state or blindly reinstalling. Code rollback packages previous source as a higher plugin version. Do not publish a release as part of installation or testing. Record the tested Premiere version and any stale Text-panel workaround from the native validation guide.

```


Unified People updates: follow [People migration and review](../PEOPLE.md). Candidate activation must pass the data-capability downgrade guard. Validate naming, audio playback, visible/heard appearances and a saved/reopened review decision on a disposable project.
