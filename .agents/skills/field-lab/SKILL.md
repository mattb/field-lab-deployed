---
name: field-lab
description: Install, update, check, or recover the local Field Lab OffShoot and AI indexing workflow on an Apple Silicon Mac, including offline field updates and explicitly requested smaller-drive backup rotation. Updates adopt the selected release’s scoped workflow migrations.
---

For any update request, including one containing only the repository URL, read `docs/UPDATE.md` from the current repository first. Resolve and pin the newest published release including prereleases when no ref is specified; then read that release's manifest and instructions. Apply its workflow migrations without requiring a separately pasted adoption prompt. Explicit software-only requests stay software-only. Do not let a stale installed copy of this skill choose a stale version or skip the new release plan.

Use the repository scripts rather than rebuilding the procedure in shell. This skill can be installed globally; its installation folder is not necessarily the application repository. Find an existing source checkout of `https://github.com/mattb/field-lab-deployed` in the current workspace, checking its Git origin and local changes. If none is present, clone that repository into a new source folder outside media (default `~/Dev/field-lab-source`); preserve any existing folder rather than replacing it. Resolve the operator's requested tag/commit there before executing code. When invoked from this repository's `.agents/skills/field-lab` folder, its source checkout is three parent folders up. All paths below refer to that verified checkout, never to parents of a globally installed skill. Read the checkout's `AGENTS.md`, `docs/OPERATIONS.md`, then only the matching prompt under `docs/prompts/`. Installing the skill alone does not install models or applications; continue with the requested first-install/update using the checkout.

For a first install, use `docs/prompts/FIRST-INSTALL.md`. For an existing installation, use `docs/prompts/FIELD-UPDATE.md`. The public entry point is `bash deploy/bootstrap.sh`; it obtains the pinned Python and invokes `deploy/field.py`. Run `--help` or `status` before mutations if flags are uncertain. Installed state defaults to `~/Library/Application Support/Field Lab`; source checkout and installed releases are separate.

An install/update request authorizes downloading dependencies and preparing a candidate. Activate when the requested scope includes deployment and OffShoot is confirmed to have no active or queued transfers; record that confirmation using `--offshoot-idle`. This flag asserts observed/operator-confirmed state, it does not discover idle state. If idle cannot be established, finish candidate preparation and report the remaining switch step. Do not treat an elapsed timeout as idle. Use `--interrupt-ai` only if the operator wants an unfinished AI run interrupted; startup reconciles its backlog.

Choose an explicitly identified mounted destination on first configuration; do not copy developer volume names or UUIDs. `configure` derives the mounted UUID. Configure OffShoot only after activation, using `configure-offshoot --offshoot-idle` and the app's Disks screen. It backs up the affected settings, sets verified copies and stable hooks, and changes OffShoot destinations. Ordinary updates do not rerun it. The release manifest may require dedicated Field Lab CCC setup as part of an unqualified update; establish the actual destination before applying it. Explicit software-only updates leave CCC unchanged.

For a USB camera visible only in Image Capture/MTP, or one exposed through MacDroid, read `docs/MACDROID-INGEST.md`. MacDroid is an optional operator-selected source adapter, not an install prerequisite or ingest destination. Discover its actual folder, preserve companions, and select it as an OffShoot folder source; keep the existing receipt gate and physical destination checks. Folder enumeration does not prove a completed transfer or independent device rereading through a cache. Require the adapter-specific acceptance test; X10 compatibility remains untested. Do not install/configure MacDroid or change camera USB mode merely as part of an ordinary software update.

Keep all source footage and `_DIT_NOTES` outside application releases. Never delete or reset project data, queues, names, matching feedback, or receipts to fix an installation. Do not import demo media or seeded identities. Do not run `git pull` inside an active release. Fetch/check out an operator-approved tag or commit in the source checkout, prepare it separately, and switch using the manager. Never claim Git tag authenticity merely from a locally calculated checksum.

Before switching, the scripts check pinned asset integrity and offline readiness. After switching, use `docs/SMOKE-TEST.md` with an operator-selected disposable clip and check `doctor`; a ready manifest alone does not prove model inference or an actual OffShoot transfer. Record what was actually tested. A failed preparation leaves current running code intact. Rollback selects prior code; it does not downgrade project databases. Preserve pre-update backups and stop if a schema downgrade is uncertain.

Report active version, configuration location, offline readiness, smoke-test coverage, remaining backlog/errors, and whether OffShoot/CCC were changed. Do not promise universal codec or camera-card support from a synthetic test.

For a prompt, model or UI upgrade, read `docs/UPGRADES.md`. Run `reindex --project PROJECT` to plan registered-scope work; the plan does not clear an index. Run with `--run --offshoot-idle` only when reanalysis is requested and the AI service is stopped. A UI-only update should reuse AI outputs. After a server/UI update, reopen or reload the browser; built assets and responses have cache-safe URLs/headers. Use `verify-offshoot` for preference/preset readback after integration changes. For separately requested CCC setup read `docs/CCC-SETUP.md`; `ccc-status` is read-only, task creation uses supported CCC UI rather than undocumented preference writes.

After first activation and machine configuration, create the requested Desktop launchers using the checkout's `desktop` command and `docs/DESKTOP.md`. They are locally built Mac apps with stable release-independent targets. Never replace an unrelated Desktop item. Ingest opens OffShoot; it does not automatically select cards, queue a transfer or erase anything. Existing launchers follow updates without reinstallation.

For an explicit smaller-drive backup rotation request, read `docs/BACKUP-ROTATION.md` and use the repository’s `field-lab-backup` skill. CCC remains the copying engine and reads the original project root directly. Previous tasks explicitly Include assigned date/card folders; the current task Excludes all older assignments so new ingests need no daily filter edits. Preserve all unrelated CCC tasks and private assignment/verification records. Configure only operator-authorized dedicated tasks through Bombich-supported UI controls. No published headless filter configuration API has been established: do not generate undocumented task/filter formats, reverse engineer CCC or promise automatic configuration from a Desktop action. A plan is not proof of applied configuration or a verified backup. The earlier rotation commands are withdrawn; never delete existing backup data or ledgers as part of that change. No source card release is automatic.


For a requested Premiere bridge install/update, read `docs/PREMIERE-INSTALL.md` and use `bash deploy/bootstrap.sh premiere ...`. Stage only sealed allowlisted runtime files; Use `premiere package` with the pinned Adobe SDK implementation (or UDT Package followed by `attach-ccx`); both verify the CCX against the staged seal. Never rename a homemade ZIP to CCX or copy files into Adobe registries. Install using Adobe UPIA only after saving and quitting Premiere; preserve all project journals and user-scoped pairing permissions. The plugin version must increase for an update. On an interrupted/unknown Adobe outcome, use `premiere reconcile` before another attempt; never clear the ledger or uninstall to force a downgrade. A previous-code rollback is repackaged under a higher plugin version. Runtime readiness requires `verify-runtime` against a fresh saved operation in the actual project database, matching package ID/version/module hashes. A UPIA listing alone is not native workflow proof. Packages contain no models or footage; offline installation still requires installed/licensed Adobe apps and a local verified CCX. Packaging does not authorize publishing a GitHub/Marketplace release or changing OffShoot/CCC.


Unified People updates: follow [People migration and review](../../../docs/PEOPLE.md). Before first access, the application backs up the SQLite registry and verifies that migration leaves legacy evidence unchanged. Preserve the receipt; never restore an old database over later edits. Candidate activation must pass the data-capability downgrade guard. Validate naming, audio playback, visible/heard appearances and a saved/reopened review decision on a disposable project.


The `desktop` command also installs the native **Backup.app** on the recipient Mac. It has no predefined CCC task. Preserve any existing private current-task binding during updates. For a manifest-required CCC migration or explicitly requested backup setup, use the checkout's [field-lab-backup skill](../field-lab-backup/SKILL.md) to configure and verify dedicated tasks, then bind Backup to the actual current task UUID. With no configured task, leave it unbound and report that state. Do not select a convenient existing task as a default. At each completed rotation, that skill updates the binding last; the Desktop icon stays unchanged. Treat recipient setup instructions as instructions for the target Mac, not authorization to install shortcuts on the maintainer's development Mac while editing this repository.

For the manifest-required backup migration during a normal update, or an explicit adoption request, follow `docs/prompts/UPDATE-AND-ADOPT-BACKUPS.md` and `docs/BACKUP-ADOPTION.md` after activating the new release. An explicitly software-only request skips adoption; an unqualified update includes manifest migrations. Discover/reconcile older task/assignment state, configure the original-source date filters in supported CCC UI, retain private atomic records, then bind Backup last. Never report adoption complete merely because desktop installation succeeded.
