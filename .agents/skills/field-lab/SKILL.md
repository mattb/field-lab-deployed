description: Install, update, check, or recover the local Field Lab OffShoot and AI indexing workflow on an Apple Silicon Mac, including offline field updates and explicitly requested smaller-drive backup rotation. CCC configuration remains a separate explicit operation.
---

Use the repository scripts rather than rebuilding the procedure in shell. This skill can be installed globally; its installation folder is not necessarily the application repository. Find an existing source checkout of `https://github.com/mattb/field-lab-deployed` in the current workspace, checking its Git origin and local changes. If none is present, clone that repository into a new source folder outside media (default `~/Dev/field-lab-source`); preserve any existing folder rather than replacing it. Resolve the operator's requested tag/commit there before executing code. When invoked from this repository's `.agents/skills/field-lab` folder, its source checkout is three parent folders up. All paths below refer to that verified checkout, never to parents of a globally installed skill. Read the checkout's `AGENTS.md`, `docs/OPERATIONS.md`, then only the matching prompt under `docs/prompts/`. Installing the skill alone does not install models or applications; continue with the requested first-install/update using the checkout.

For a first install, use `docs/prompts/FIRST-INSTALL.md`. For an existing installation, use `docs/prompts/FIELD-UPDATE.md`. The public entry point is `bash deploy/bootstrap.sh`; it obtains the pinned Python and invokes `deploy/field.py`. Run `--help` or `status` before mutations if flags are uncertain. Installed state defaults to `~/Library/Application Support/Field Lab`; source checkout and installed releases are separate.

An install/update request authorizes downloading dependencies and preparing a candidate. Activate when the requested scope includes deployment and OffShoot is confirmed to have no active or queued transfers; record that confirmation using `--offshoot-idle`. This flag asserts observed/operator-confirmed state, it does not discover idle state. If idle cannot be established, finish candidate preparation and report the remaining switch step. Do not treat an elapsed timeout as idle. Use `--interrupt-ai` only if the operator wants an unfinished AI run interrupted; startup reconciles its backlog.

Choose an explicitly identified mounted destination on first configuration; do not copy developer volume names or UUIDs. `configure` derives the mounted UUID. Configure OffShoot only after activation, using `configure-offshoot --offshoot-idle` and the app's Disks screen. It backs up the affected settings, sets verified copies and stable hooks, and changes OffShoot destinations. Ordinary updates do not rerun it. CCC stays untouched unless separately requested with a known second destination.

For a USB camera visible only in Image Capture/MTP, or one exposed through MacDroid, read `docs/MACDROID-INGEST.md`. MacDroid is an optional operator-selected source adapter, not an install prerequisite or ingest destination. Discover its actual folder, preserve companions, and select it as an OffShoot folder source; keep the existing receipt gate and physical destination checks. Folder enumeration does not prove a completed transfer or independent device rereading through a cache. Require the adapter-specific acceptance test; X10 compatibility remains untested. Do not install/configure MacDroid or change camera USB mode merely as part of an ordinary software update.

Keep all source footage and `_DIT_NOTES` outside application releases. Never delete or reset project data, queues, names, matching feedback, or receipts to fix an installation. Do not import demo media or seeded identities. Do not run `git pull` inside an active release. Fetch/check out an operator-approved tag or commit in the source checkout, prepare it separately, and switch using the manager. Never claim Git tag authenticity merely from a locally calculated checksum.

Before switching, the scripts check pinned asset integrity and offline readiness. After switching, use `docs/SMOKE-TEST.md` with an operator-selected disposable clip and check `doctor`; a ready manifest alone does not prove model inference or an actual OffShoot transfer. Record what was actually tested. A failed preparation leaves current running code intact. Rollback selects prior code; it does not downgrade project databases. Preserve pre-update backups and stop if a schema downgrade is uncertain.

Report active version, configuration location, offline readiness, smoke-test coverage, remaining backlog/errors, and whether OffShoot/CCC were changed. Do not promise universal codec or camera-card support from a synthetic test.

For a prompt, model or UI upgrade, read `docs/UPGRADES.md`. Run `reindex --project PROJECT` to plan registered-scope work; the plan does not clear an index. Run with `--run --offshoot-idle` only when reanalysis is requested and the AI service is stopped. A UI-only update should reuse AI outputs. After a server/UI update, reopen or reload the browser; built assets and responses have cache-safe URLs/headers. Use `verify-offshoot` for preference/preset readback after integration changes. For separately requested CCC setup read `docs/CCC-SETUP.md`; `ccc-status` is read-only, task creation uses supported CCC UI rather than undocumented preference writes.

After first activation and machine configuration, create the requested Desktop launchers using the checkout's `desktop` command and `docs/DESKTOP.md`. They are locally built Mac apps with stable release-independent targets. Never replace an unrelated Desktop item. Ingest opens OffShoot; it does not automatically select cards, queue a transfer or erase anything. Existing launchers follow updates without reinstallation.

For an explicit smaller-drive backup rotation request, read `docs/BACKUP-ROTATION.md` and use `bash deploy/bootstrap.sh backup ...` with the active release. This is opt-in: ordinary install/update never enables it or changes CCC tasks. Select the actual project, separate same-APFS clone spool and independent backup drives. Use only NEW dedicated operator-reviewed CCC tasks, registered UUIDs and secured standalone task-specific preflight guards; never modify/start an existing unrelated task or run user-writable Python as root from CCC. Do not fabricate `.ccctask` files. Guide the one-time UI/admin steps when their supported controls require operator interaction, then perform the disposable physical acceptance test. Launch the loopback backup UI with the correct verified-ingest queue; opening it does not start copying. Pending work/unknown attempts resume against the same checksummed ledger, never by clearing it. Retain metadata generations, drive assignments and manifests across updates; do not propagate arbitrary Finder reorganization across archived sets or silently prune snapshots. Explain any untested CCC/physical-drive step and leave it pending. No source card release is automatic.
