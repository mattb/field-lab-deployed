---
name: field-lab-cutover
description: Change a Field Lab shoot's ingest primary to another mounted volume, retain per-primary CCC backup pairs, or recover an interrupted primary cutover. Reconnecting or browsing an old drive alone must not change the ingest primary.
---

Read the verified source checkout's `AGENTS.md` and [multi-primary procedure](../../../docs/MULTI-PRIMARY.md). If globally installed, find the actual repository as described by the main Field Lab skill; documentation paths refer to that repository. Use its `deploy/bootstrap.sh primary` and `cutover` commands, not hand-edited registry/config files. Developing this skill does not authorize changing the maintainer's installed apps or disks.

1. Inspect actual installed version/capabilities, shared configuration, primary registry, pending intent, service state and external apps. Adopt the configured mounted primary with `primary init` only when no shoot registry exists. Establish operator-selected mounted endpoints and UUIDs; never choose a developer default or create a missing mount directory. After initialization, enroll existing active-primary CCC pairs/current set and reconcile its existing assignments into the returned per-primary ledger path before relying on Backup; initialization does not migrate them automatically. Preserve all prior records. Register the new volume inactive and retain its returned stable ID. A label is not identity.
2. Finish transfers, observe OffShoot/CCC idle and stop AI; run guarded `cutover prepare --primary ID --offshoot-idle` to cache the old library and create the verified new project root before selecting that source in CCC. Create/read back only the target's dedicated CCC tasks in supported UI. CCC alone copies originals directly. Follow the [backup skill](../field-lab-backup/SKILL.md), using `primary ledger-path --primary ID` for separate assignments. Register observed endpoints with `backup-register`, select its per-primary current set with `backup-current`. Existing old tasks/pairs remain intact. Do not generate private CCC settings or claim its start/monitor CLI configures filters. A task UUID's existence does not prove its current source/destination; inspect actual settings and Preview.
3. Finish OffShoot transfers; establish observed idle and CCC idle; stop AI and metadata writers. Run `cutover prepare --primary ID --offshoot-idle`, then `apply --offshoot-idle`, with `--home` before the action. Apply may have external side effects before interruption. Read back the pending journal and actual app state on every retry. Do not delete an intent or start another target to bypass recovery.
4. Run `cutover validate` while the intent is pending. Ordinary startup/Backup intentionally remains blocked. Observe target OffShoot dropzones, perform a verified disposable ingest, inspect indexing and saved/reopened metadata. Stop AI and operator writes before the target CCC validation copy; invoke `backup-shortcut run --primary ID --set-label LABEL --validation-intent INTENT_ID`. Inspect CCC verification and restore/read evidence. Preserve source cards.
5. With validation service stopped, prepare fresh target-specific operator acceptance evidence exactly as documented. Never fabricate true flags/artifacts from test success, settings readback or a process exit. `accept` records attestation, not independent proof. Run `finish`, explicitly restart, verify normal launch/status and report exact coverage. Do not change the accepted target's backup selection before finish.

Keep laptop metadata/index/preview caches and registry history across updates; originals stay on their volumes. Capability `multi_primary: 1` blocks unsupported older writers. Rollback of code cannot undo registry adoption, external app changes or subsequent metadata. No blanket reindex, identity merge, clear/reset or copied demo database is part of cutover.

For old drives, browse or explicitly run that primary's registered backup pair without rebinding Desktop Backup or changing active ingest. If an inactive mount changes, use `primary refresh-mount`, then review/re-register task sources. A wrong UUID is a stop condition. Source reorganization requires filter/assignment reconciliation. Unknown prior CCC starts require supported task-history reconciliation, never automatic repeated starts.

Report active and pending primaries, actual OffShoot/CCC changes, target current set, old pairs retained, validation artifacts, cache errors and unresolved steps. Local-folder tests are not real recipient acceptance. If supported app control or a required disk is unavailable, retain the recoverable pending state and identify the remaining concrete check; do not claim completion.
